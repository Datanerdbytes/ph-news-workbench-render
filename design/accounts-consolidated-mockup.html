Open decisions

Four switches left to settle

Each has a default in the plan, so the build can start without them — flip any of them with a one-line change.

D1

Does /accounts keep the “Facebook Page” nav group?

Today /platforms hides the Facebook-only tools and /accounts shows them. The merged page is a cross-platform hub.

Default: hide it

D2

What happens to the platforms footer?

Its privacy paragraph goes; the “Per-channel capability matrix” link now points at a table on the same page.

Default: keep shell, in-page anchor

D3

Where do the review gates live?

“Google verification”, “Content Posting audit”, “Community API access” — per card note, or a slim section below the grid.

Default: in the card note

D4

Capability info shows twice

Per-card chips plus the matrix table. The chips are tested behaviour; the table is the cross-platform view.

Default: keep both
One coordination risk: the working tree already deletes app/api/youtube/** and app/youtube/page.tsx. When that lands, the YouTube card degrades to “Status unavailable” and its Launch link points at a missing page. The merged page must not depend on any YouTube route — the card can be dropped as a separate follow-up.
